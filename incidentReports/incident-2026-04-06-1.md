# Incident: 2026-04-06 19-00-00 UTC

## Summary

```md
Between the hour of 18:45 UTC and 19:00 UTC on 2026-04-06, 2 users encountered a blocking of any pizza order requests made to the external Pizza Factory. The event was triggered by a scheduled chaos-testing event right when the error began occurring. The chaos testing was validated with a URL, resolving the block and restoring normal functionality to the users.

The event was detected by our metrics sent to our Grafana Cloud dashboard, which has a set of alert rules monitoring each metric for extraordinary and/or blocking behavior. The team started working on the event by investigating the Pizza Factory Order Loki logs which had a status code of 500 and a descriptive message defining it as a result of the chaos testing period. This "Error" level incident affected 100% of users.
```

## Detection

```md
This incident *would have been* detected when the Alert Rule `Factory 500+ Status Level Error` was triggered, which keeps a count of 500-level errors for any logs of requests made to the JWT Pizza Factory and if that count exceeds 5 in a passing 5 min. period, and Bentley, on the JWT Pizza DevOps Team, would have beeen paged.

However, Bentley was performing routine checks, keeping his device active/from falling asleep and noticed immediately in his Grafana metrics dashboard the chaos-related Loki logs with a 500 status code and the associated message.

An anticipated improvement to the metrics and alert rules would be to reduce the count required to trigger the rule from 5 to something like 3, so that the team can be notified sooner since the chaos testing induced a blocking error of the primary function of the site for all users.

```

## Impact

```md
This incident affected 2 customers (100% OF SERVICE USERS), who experienced a blocked attempt to place an order for a pizza to the Pizza Factory.

0 support tickets were submitted.
```

## Prevention

```md
In the future, we would schedule Chaos Testing with our users notified in advance and at a time that is not naturally highest traffic so that we could impact a minimal amount of real users, giving real experience in addressing increased load when it is natural and occurs while not being at the cost of significant business.

I will also need to diagnose why some of my Loki Log-based alert rules, as some of the issued "false-positive" alerts throughout the day for "Missing Data Source." Even meeting with a TA, we could not diagnose why only the Loki Logs experienced these alert triggers.
```
